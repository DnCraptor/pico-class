# Исходники программ для pico-pce (PC Engine)

Программы на C с карты `sdcard/PCE/*.pce`. Написаны для этого репозитория и распространяются на условиях [`LICENSE`](../../LICENSE). Это обычные картриджи HuCard по 32 КБ, без маппера.

| Файл | Картридж | Что показывает |
|---|---|---|
| `hello.c` | [`hello.pce`](../../sdcard/PCE/hello.pce) | текст на экране (`put_string`, `put_number`), цвета палитры (`set_color`), часы на счётчике кадров (`vsync`), нажатые кнопки геймпада (`joy`, `joytrg`), звук |
| `sprite.c` | [`sprite.pce`](../../sdcard/PCE/sprite.pce) | аппаратные спрайты: робот на геймпаде, мяч летает сам и отскакивает от краёв, касание считается; кнопка I меняет палитру робота |
| `catch.c` | [`catch.pce`](../../sdcard/PCE/catch.pce) | законченная игра «Лови звёзды»: корзина внизу, три звезды падают всё быстрее, три промаха — конец игры, лучший счёт запоминается |
| `beep.h` | — | звук: прямоугольная волна на канале 0 звукового чипа (PSG), регистры `0x0800`–`0x0806` через `poke` |
| `mksprites.py` | — | спрайты нарисованы в нём текстом (цифра — номер цвета палитры) и превращаются в данные `sprite_gfx.h`, `catch_gfx.h` |

Кнопки геймпада PC Engine: I, II, SELECT, RUN. В pico-pce на клавиатуре: стрелки (или WASD) — крестовина, **Z** — I, **X** — II, **Enter** — RUN, **Esc** или **Backspace** — SELECT; **Enter+Esc** — меню эмулятора (выход к выбору картриджа). Геймпад NES: A — I, B — II, Start — RUN, Select — SELECT.

Тексты на экране — латиницей: во встроенном шрифте HuC нет кириллицы.

## Сборка

Компилятор — HuC из набора [pce-devel/huc](https://github.com/pce-devel/huc) (проверено на `54f5c73`, 2026-09-09). Сначала собрать набор (`make` в его корне), затем из этого каталога:

```sh
HUC=/путь/к/huc ./build.sh
```

`build.sh` запускает `mksprites.py`, компилирует три программы (`huc -fno-recursive -msmall`) и кладёт картриджи в `../../sdcard/PCE`. Сборка повторяемая: те же исходники дают побайтово те же файлы. Расширение — строчными буквами: pico-pce показывает в списке только файлы `*.pce`.

Нужен именно `huc`, а не новый `hucc` из того же набора: программы `hucc` ждут прерывания кадра так, что ядро pico-pce его не выдаёт, и останавливаются на первом `vsync()`.

Картриджи проверены на ядре pce-go из [DnCraptor/pico-pce](https://github.com/DnCraptor/pico-pce) (`a790a67`), собранном для ПК: экран после старта, отклик на кнопки, звук, счёт в `sprite.pce` и `catch.pce` (для проверки корзину и робота водила программа).
